# Manual security tests

The manual tests listed in [05 §12](../design/05-security-review.md#12-manual-security-tests-phase-7), with the procedure, the expected result and what is already covered by automated tests. A tester runs them against a **staging deployment** with fictional data before the pilot. Record the date, tester, build and outcome for each in the Phase 8 test record.

Automated coverage does not replace the manual run: the manual run exercises the real deployment (proxy, TLS, email, file storage) and tries variations an automated test does not.

| # | Test | Procedure | Expected result | Automated coverage | Manual status |
|---|---|---|---|---|---|
| 1 | Object references across organisations and roles | Signed in to organisation A, replace `org_slug`, `election_id`, `nomination_id`, `member_id` and `document_id` in every URL with organisation B's, and with objects A's role should not reach. Repeat for GET and POST, and with a browser proxy. | 404 for other organisations, identical to an unknown organisation; 403 or 404 for roles without permission. | Every organisation URL, automatically discovered: `tests/test_tenant_isolation_http.py`; database level: `tests/test_tenant_isolation_db.py` | Pending |
| 2 | Ballot form tampering | With a proxy, alter the review and cast requests: extra candidate ids, ids from another election, duplicates, more than the maximum, an empty ballot when blanks are not allowed, a forged or another voter's idempotency key, a malformed receipt commitment. | Nothing recorded; a clear "not accepted" page; the entitlement stays issued. | `test_invalid_selections_are_rejected_and_nothing_is_recorded`, `test_forged_or_foreign_idempotency_keys_are_rejected`, `test_partial_and_blank_ballot_rules` | Pending |
| 3 | Session fixation, reuse after logout, CSRF | Set a session cookie before login and check it changes; replay a session cookie after logout; submit every form from another origin and without the token. | New session key at login; old cookie rejected after logout; every POST without a valid token refused (403). | `test_session_key_rotates_on_login`, `test_logout_requires_post`, CSRF middleware on all views | Pending |
| 4 | Account enumeration | Compare responses and timings for unknown email vs wrong password, and on invitation acceptance; check lockout behaviour for unknown emails. | Identical messages; similar timings; lockout applies equally. | `test_wrong_password_and_unknown_email_look_identical`, `test_lockout_applies_equally_to_unknown_emails` | Pending (timing needs the real deployment) |
| 5 | Step-up bypass | With a session older than 5 minutes since the last code, call privileged endpoints directly (schedule, count, tie, certify, publish, role grants, imports) by GET and POST. | Redirected to "Confirm it's you"; no action taken. | `test_step_up_redirects_when_mfa_is_stale`; `step_up_required` on each view | Pending |
| 6 | Changing a scheduled election | After scheduling, try to change rules, seats, times, candidates and the electorate through the UI, by crafted POSTs, and directly in the database as `app_rw`. | Refused at every layer; the history is unchanged. | `test_configuration_locked_after_submission_and_closed_is_final`, `test_shares_cannot_be_changed_or_added_later`, `test_electorate_and_entitlement_guards` | Pending |
| 7 | Reading ballots and key shares from other roles | As `app_rw` and `app_platform`, select from `ballot`, `key_share`, `key_contribution`. | `ballot`: permission denied. Key shares: only sealed bundles, useless without passphrases. | `test_web_role_cannot_read_or_write_the_ballot_box`, `test_web_role_cannot_write_tallies_and_tally_role_cannot_read_receipts`, `test_table_privileges_match_manifest_exactly` | Pending |
| 8 | Upload abuse | Upload a polyglot PDF, an oversized file, a file with a wrong extension or MIME type, and the EICAR test file. | Refused by content type or size (the plain EICAR file is refused as not a PDF, JPEG or PNG). EICAR embedded in a valid PDF: **accepted and marked "not scanned"** until finding F-4 is fixed. | `tests/test_nominations.py` upload tests | Pending (F-4 open) |
| 9 | Leak search | Vote with a canary candidate name; then search application logs, proxy logs, the error tracker, email and the database (outside `ballot`) for the canary and for receipt codes. | No occurrence linked to a voter. | `test_no_choice_leaks_into_logs_audit_email_or_sessions`, `test_counting_never_records_how_anyone_voted`, `test_admin_and_audit_views_disclose_no_choices` | Pending |
| 10 | Audit chain tampering | As a database superuser, change an old audit event; then run "Verify the audit chain" and `manage.py verify_audit`. Repeat after recomputing the following hashes and the anchor row. | Detected in both cases (the second through the anchor file). | `tests/test_audit_chain.py` tamper tests | Pending |
| 11 | Restore drill | Restore a real backup into an isolated environment and run `manage.py post_restore_check`, then a test recount of a fictional election. | All checks pass; recount equals the original. | `tests/test_restore_drill.py` (CI) | Pending (on real infrastructure) |
| 12 | Mobile browsers | Run a full fictional election on real devices: low-end Chrome on Android, Safari on iOS, Samsung Internet. Include poor-network behaviour (airplane mode during cast). | Every step works; a lost connection never shows a false "accepted" and never creates a second ballot. | `e2e/run.sh`: Chromium (Pixel 7) and WebKit (iPhone 14) emulation in CI | Pending (real devices) |
